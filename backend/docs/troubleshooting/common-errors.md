Deep-Dive Troubleshooting Scenarios3.1 Scenario A: Optimistic Concurrency Control (OCC) Failures (CONCURRENCY_CONFLICT)Symptom: API returns a 409 conflict when a technician attempts to update a repair ticket or asset record.Diagnosis: Entity version mismatch. The database trigger or EF Core change tracker detected that the version column value in the database is higher than the version submitted in the update payload.Resolution:Re-fetch the latest record state via GET.Merge any local changes onto the fresh entity state.Submit the updated payload containing the new version integer.3.2 Scenario B: Idempotency Lock CollisionsSymptom: Mutating requests (e.g., financial transactions, reservation bookings) fail immediately when retried after a transient network drop.Diagnosis: The X-Idempotency-Key header submitted by the client matches an existing record in audit.idempotency_locks.Resolution: Ensure clients generate a unique UUIDv4 X-Idempotency-Key for every unique logical user action. For genuine retries of failed requests, the system safely replays the original cached response.3.3 Scenario C: Nginx Gateway Timeouts on AI RAG Queries (UPSTREAM_TIMEOUT)Symptom: HTTP 504 Gateway Timeout when submitting complex diagnostic prompts or large knowledge base searches to /api/v1/ai/chat/completions.Diagnosis: The Python AI container is taking longer than the default Nginx proxy timeout (60 seconds) to compute vector similarity embeddings or run transformer generation.Resolution: Ensure the Nginx location block for AI routes explicitly increases the read timeout:Nginxproxy_read_timeout 120s;
proxy_send_timeout 120s;
4. Diagnostic SQL & Container Commands4.1 Check Active Database Locks & Blocking QueriesSQLSELECT 
    blocked_locks.pid     AS blocked_pid,
    blocked_activity.usename  AS blocked_user,
    blocking_locks.pid    AS blocking_pid,
    blocking_activity.usename AS blocking_user,
    blocked_activity.query    AS blocked_statement,
    blocking_activity.query   AS current_statement_in_blocking_process
FROM pg_catalog.pg_locks         blocked_locks
JOIN pg_catalog.pg_stat_activity blocked_activity ON blocked_activity.pid = blocked_locks.pid
JOIN pg_catalog.pg_locks         blocking_locks 
    ON blocking_locks.locktype = blocked_locks.locktype
    AND blocking_locks.database = blocked_locks.database
    AND blocking_locks.relation = blocked_locks.relation
    AND blocking_locks.page = blocked_locks.page
    AND blocking_locks.tuple = blocked_locks.tuple
    AND blocking_locks.virtualxid = blocked_locks.virtualxid
    AND blocking_locks.transactionid = blocked_locks.transactionid
    AND blocking_locks.classid = blocked_locks.classid
    AND blocking_locks.objid = blocked_locks.objid
    AND blocking_locks.objsubid = blocked_locks.objsubid
    AND blocking_locks.pid != blocked_locks.pid
JOIN pg_catalog.pg_stat_activity blocking_activity ON blocking_activity.pid = blocking_locks.pid
WHERE NOT blocked_locks.granted;
